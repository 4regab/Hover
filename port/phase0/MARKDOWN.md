# What `md.js` and `diagram.js` actually support

This is what the current code does. It is neither CommonMark nor Mermaid. The Rust
ports (`native/crates/hover-md`, `native/crates/hover-diagram`) must produce the same
output. Golden files generated by running the JS itself check this
(`native/golden/gen.mjs`).

## Blocks (`markdown()`), tried in this order on each line

1. **Fence**: `^\s*(```+|~~~+)\s*([\w+#.-]*)`. The body runs up to the first later line
   whose trimmed text *starts with* the same fence string; that line is consumed. An
   unclosed fence runs to the end. The language is lowercased. `mermaid` goes to
   `flowchart()`; if that returns null, the fence is shown as code. The output is
   `<pre class="code" data-lang="…"><code>…</code></pre>` (no `data-lang` when empty) or
   `<figure class="diagram">svg</figure>`.
2. **Blank line**: ends the paragraph.
3. **Heading**: `^\s{0,3}(#{1,6})\s+(.*?)\s*#*\s*$`. The level is shifted by +2 and capped
   at 6 (`#` → h3 … `####`+ → h6).
4. **Rule**: `^\s{0,3}([-*_])(\s*\1){2,}\s*$` → `<hr>`.
5. **Table**: a line containing `|` followed by a delimiter row
   `^\s*\|?\s*:?-{2,}:?\s*(\|\s*:?-{2,}:?\s*)*\|?\s*$`. Cells are split on unescaped `|`,
   with the outer pipes stripped. Alignment is `:x:` centre, `x:` right. Rows continue while
   the line contains `|` and is not blank. The column count comes from the header; missing
   cells are empty. The table is wrapped in `<div class="table">`.
6. **Quote**: consecutive lines matching `^\s{0,3}>`. Each has `^\s{0,3}>\s?` removed and
   the result is parsed recursively as a full document.
7. **List**: `^\s*([-*+]|\d+[.)])\s+`. See below.
8. Otherwise the trimmed line joins the **paragraph**. Paragraph lines are joined with
   `\n`, then run through inline, then `\n` becomes `<br>`. There is no lazy continuation
   into lists or quotes.

### Lists
- The indent is the first item's leading whitespace. An item with more indent starts a
  nested list, which is appended to the previous item (it is dropped if there is none).
  An item with less indent ends the list.
- A bullet item after a numbered one, or the other way round, ends the list.
- A numbered list writes `start="n"` when it starts at n ≠ 1. The value comes from
  `parseInt` of the trimmed line.
- A blank line inside a list is skipped only when the next line is a list item.
- Continuation lines are indented, non-blank lines that are not list items. They are
  joined with `\n`, but no `<br>` is emitted inside list items: the newline stays as
  whitespace.
- Task items: `^\[([ xX])\]\s+` becomes `<span class="task[ done]"></span>`.

## Inline (`inline()`), in this order
1. Code spans ``(`+)([\s\S]*?[^`])\1(?!`)``: the content is trimmed and escaped, set aside,
   and emitted as `<code>`.
2. HTML escape of `& < > " '` for everything else.
3. Images `![alt](src "title")`: src passes through `o.image(src)`. If that returns null,
   the source text is left as is. alt is inserted already escaped. The output is
   `loading="lazy"`.
4. Links `[label](href "title")`: only `http(s)://` becomes a link. Otherwise the label
   alone remains. The title is not used; `title` is set to the URL.
5. Bare `https?://` addresses after start, whitespace or `(`. Trailing `.,;:!?)` is not
   part of the link.
6. `**x**` / `__x__` → strong; `*x*` / `_x_` → em (not inside words); `~~x~~` → del.
   Marks can cross link placeholders but never enter code spans.

No raw HTML passes through, and there are no autolinks `<…>`, setext headings, indented
code blocks, reference links, footnotes or hard-break spaces.

## Images an answer can show (`imageFor`, main.js)
- `http(s)://` URLs load directly.
- Anything else only when the session has a files host. `file:///` is stripped, `\` becomes
  `/`, and the path is URL-decoded. An absolute `X:/` path must lie inside the session
  folder (case-insensitive) and is made relative. `./` is stripped. A path starting with
  `/` or containing `..` is rejected. The URL is `https://f<key12>.hover/<encoded path>`.

## Flowcharts (`diagram.js`)
- Header `graph|flowchart [TD|TB|BT|LR|RL]` (default TD). `%%` comments are removed. The
  source is split on newlines **and `;`**.
- Nodes are `id` optionally followed by a shape: `([ ])` stadium, `(( ))` circle,
  `[[ ]]` sub, `[( )]` db, `{{ }}` hex, `[ ]` box, `( )` round, `{ }` diamond, `> ]` flag.
  Quoted labels are unquoted, and `<br>` becomes a newline.
- Edges: `-->`, `---`, `-.->`, `-.-`, `==>`, `===`, `--o`, `--x`, with `|label|` or
  `-- text -->`. Chains (`a --> b --> c`) and `&` groups are supported.
- `subgraph`, `end`, `classDef`, `class`, `style`, `click`, `linkStyle` and `direction`
  are skipped; subgraphs are drawn flat.
- Any line it can't read makes the whole diagram null, so it is shown as code. Other
  Mermaid kinds are null too, as is a chart with more than 80 nodes.
- Layout:
  - Back edges are found by a DFS in source order; ranks are the longest path.
  - Nodes are ordered by the barycentre of their parents, with character-width sizing
    (6.6 px per char, 15 px lines, labels wrapped at 26 chars, at most 6 lines).
  - Gap 26, layer step 58. Across a left-right chart the step is widened for edge labels.
  - Edges are cubic curves between shape boundary points. Arrowheads come from marker
    `#ah`, and labels are drawn on rects.
- Styling comes from the page CSS (`.flow …` in page.html), not from the SVG itself.


## Defects found in the baseline while testing the port

Both need the user's decision. The port does not copy them.

1. **Hang.** A list-item line containing U+2028 or U+2029 (for example `- a\u2028b`)
   makes `markdown()` loop for ever, pushing `<ul></ul>`. The office page freezes, and
   node runs out of memory after about 100 s. The cause is that `list()` returns without
   advancing, because JS `.` stops at those characters. 44 of the 4 000 random corpus
   inputs hit it. The port makes progress instead: the line is read as paragraph text.
2. **Throw.** Text containing `\u0000<n>\u0000`, where n is not a code span of that
   answer, makes `esc(undefined)` throw inside `inline()`, so the chat does not render.
   The port leaves the text as `undefined`, as the other placeholder already does.

Every other output of the port is byte-identical to md.js: all fixtures in
`native/golden/fixtures`, and the 3 956 random inputs on which md.js returns.
