What this fixes

  • Nine tabs do not fit on a screen edge; ninety rows do. The deck stops having a limit, and the "+2 more" tab disappears.
  • Search arrives, which Hover has no equivalent of today.
  • Two pictures across instead of one, so nine are visible without scrolling.
  • Every note and every picture is reachable from the keyboard, which suits a tool you open a hundred times a day.
  • Shortcuts are printed in the panel rather than hidden in Settings.

The risk

  • This is the least warm of the three. It reads as a developer tool, not a sticky note. If you want people to feel something when the panel slides out, this is not it.
  • Note colours shrink to 6px dots, so colour stops being a way to recognise a note across the room.
  • Two-across thumbnails are small. A screenshot of dense text is unreadable at that size and you have to open it.

Motion

  • List rows change background only, 160ms. No movement at all, because arrow-key navigation would fight it.
  • The hover tools on a picture scale from 0.94, anchored top right, 180ms.
  • Number badges fade in when the panel is hovered, 160ms, so they are not permanent clutter.
  • Nothing animates on a keyboard shortcut.

Cost to build

  • Highest of the three. Search, a keyboard model for the list, and a new panel that does not exist yet.
  • It also changes what Hover is, so it is the one to reject fastest if it does not feel right.
